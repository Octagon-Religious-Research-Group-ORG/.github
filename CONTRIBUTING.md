# Contributing to ORG on GitHub

*How a change reaches the Octagon Religious Research Group, in five lines. GitHub shows this page in every ORG
repository that has no CONTRIBUTING of its own.*

1. **Start with the welcome.** New to GitHub? The [welcome deck](https://github.com/Octagon-Religious-Research-Group-ORG/.github/blob/main/decks/welcome.marp.pdf) and
   SOP-COM-001 *New to GitHub: your first hour* (in ORG's procedures) take you from no account to reading and answering.
2. **Ask before you build.** An idea that needs a decision is a proposal: members read it in
   [`proposals`](https://github.com/Octagon-Religious-Research-Group-ORG/proposals) and vote in ORG (Voting) on Telegram. Questions go in an **issue** on the repository.
3. **Change by pull request.** Where a repository has a `preview` branch, work there and open a "Promote" pull request
   into `main`; elsewhere open a pull request into `main`. **A person with the role merges, with a merge commit, never
   a squash**, so every author's name survives. Helpers prepare and open pull requests; they never merge.
4. **Start each commit subject with one gitmoji and a type:** `:memo: docs(scope): subject`,
   `:sparkles: feat(scope): subject`, `:bug: fix(scope): subject`. The twelve the fleet uses, and why the `:alias:`
   form, are in [GITMOJI.md](https://github.com/drasticstatic/my-template/blob/main/GITMOJI.md). It is a hint, never a block.
5. **Credit and care.** If an AI helped, end the commit with its `Co-Authored-By` line (see
   [ONBOARDING.md](ONBOARDING.md)). Never commit a password, key or anyone's private story; the secret scan stops the
   first, and the never-publish rule in ONBOARDING covers the second.

What travels to a public page is decided by an allowlist and checked by a machine that reads every file
(SOP-OPS-003 in ORG's procedures). Who to ask: the organization's owners, or [CONTACTS.md](CONTACTS.md).
